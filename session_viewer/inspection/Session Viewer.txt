# Session Viewer

High-performance browser-based geometry viewer built with Rust and WebGPU.

**Live application:** https://petrasvestartas.github.io/session/  
**Documentation:** https://petrasvestartas.github.io/session/docs/

## Mission

Develop and maintain a modular, extremely fast browser-based 3D geometry viewer.

The project has two equally important deliverables:

1. The final production application.
2. Complete, code-first tutorials that allow developers to reconstruct the final application from scratch.

The tutorials are an implementation manual, NOT a traditional programming course.

**Minimal explanations. Maximum implementation. Complete source code. Exceptional visual diagrams.**

## 1. Non-negotiable requirements

- Browser application only. No native desktop application.
- Rust and WebGPU/wgpu rendering architecture.
- Modular core independent of UI.
- CLI-compatible operations.
- FastMCP-compatible operations.
- Complete geometry and scene management.
- Complete shader and rendering-mode coverage.
- Point clouds and spatial acceleration structures.
- Gumball, layers, commands and selection.
- Efficient CPU/GPU memory management.
- Extremely responsive camera navigation.
- Complete technical documentation.
- No undocumented removal of existing functionality.

## 5. Performance

Performance is a primary engineering requirement.

The current viewer feels excessively laggy despite its appealing appearance.

Investigate and optimize:

- Camera movement.
- Pan and zoom.
- Default shaded rendering.
- Transparency.
- Arctic view.
- Large meshes.
- Large point clouds.
- Multiple objects.
- GPU buffer allocation.
- Buffer updates.
- CPU/GPU synchronization.
- Draw calls.
- Shader complexity.
- Fragment overdraw.
- Culling.
- LOD.
- Event handling.
- Render scheduling.
- Memory allocations.
- Unnecessary cloning.
- Unnecessary UI updates.

Measure before optimizing.

Record:
- FPS.
- Frame time.
- CPU time.
- GPU time where available.
- Memory consumption.
- Draw calls.
- GPU upload volume.
- Buffer allocations.
- Visible geometry.
- Point and triangle counts.

Maintain reproducible benchmarks.

Do not sacrifice visual correctness for performance.

2. Short architecture diagram.

2. Define architecture.

## 12. Definition of done

The project is complete when:

- All existing features are inventoried.
- All retained features are implemented and documented.
- The viewer remains browser-based.
- Core operations are independent of UI.
- CLI and FastMCP share the same core.
- All rendering modes are covered.
- Point clouds and octrees are covered.
- Gumball and layers are covered.
- All shaders are documented.
- The unwanted 3D matrix presentation is removed.
- The 2D rounded-rectangle presentation remains.
- Performance is benchmarked and improved.
- Camera interaction is responsive.
- Memory ownership is documented.
- Tutorials reconstruct the complete final application.

**Final objective: a fast, modular, complete browser-based geometry viewer that can be rebuilt from scratch using its own implementation documentation.**
