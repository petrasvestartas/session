# 002 · Open the GPU

To draw one pixel, the GPU needs a chain of objects. The page's canvas becomes a surface. The surface picks an adapter, one real GPU. The adapter opens a device, our connection to it, and a queue, the line we push work into. This lesson opens that chain and logs what it found. Still no pixel: that is lesson 004.

## Open the chain

`lessons/002/src/engine/gpu/device.rs` · type this, new file

`open` walks the chain in order. Instance: the wgpu library itself, told to use WebGPU in the browser. Surface: the canvas as a drawing target, `None` when there is no window, as in a test. Adapter: one GPU; the browser picks it, on your machine the low-power one wins unless `?gpu=high`. Device and queue, with one raised limit: storage buffers up to 256 MiB, for big point clouds later. Then the surface is configured: an sRGB colour format when the GPU offers one, and the canvas size. `DeviceSetup` carries the results out. `failure` is a slot for the first GPU error; in the browser errors are stored, not thrown, and a later lesson reads the slot every frame.

## Checkpoint

Run `trunk serve` and open the page with the console open. You should see three lines: `adapter: <your GPU> (DiscreteGpu, BrowserWebGpu)`, `viewer init OK - surface 2560x1440, format Bgra8UnormSrgb` with your own size, and `gpu init 40 ms` or so. The chain is open. If the first line says `software adapter`, the browser found no GPU and will draw on the CPU, slowly.
